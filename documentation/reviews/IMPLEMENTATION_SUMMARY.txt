SUPPORT / TROUBLESHOOTING
================================================================================

WEBHOOK NOT RECEIVED?
  1. Check: curl http://localhost:8000/webhooks/shopify/order-created
     (Expect 405 — POST only)
  
  2. Verify Shopify store in DB:
     SELECT store_url, is_active FROM shopify_stores;
  
  3. Check webhook URL is publicly accessible (not localhost)
  
  4. Verify HMAC secret matches in ShopifyStore.webhook_secret
  
  5. Check backend logs:
     docker compose logs backend | grep webhook

TRACKING NOT UPDATING?
  1. Verify delivery partner credentials:
     SELECT partner_type, is_active, api_key FROM delivery_partners;
  
  2. Check shipment has tracking_number:
     SELECT id, tracking_number, shipping_partner FROM shopify_orders;
  
  3. Manually trigger sync:
     curl -X POST http://localhost:8000/api/shipments/sync-all -H "Authorization: Bearer $T"
  
  4. Check worker logs:
     docker compose logs backend --tail=50 | grep -i tracking

NOTIFICATIONS NOT SENDING?
  1. Check notification_logs table:
     SELECT * FROM notification_logs WHERE sent_at IS NULL ORDER BY created_at DESC;
  
  2. Verify WhatsApp API credentials in environment
  
  3. Check phone format: Must be +91XXXXXXXXXX
  
  4. Review error column in notification_logs for API error details

RISK ASSESSMENT TOO STRICT/LENIENT?
  1. Review risk_reasons for a specific order:
     SELECT risk_reasons FROM order_risk_assessments WHERE shopify_order_id='...';
  
  2. Adjust weights in RiskEngine.assess_order():
     - Customer: 35% (change to 30% for lenient)
     - Pincode: 25% (change to 15% for lenient)
     - Order value: 20%
     - COD: 20%
  
  3. Update thresholds:
     - score < 40: APPROVE (change to < 50 for more lenient)
     - score ≥ 70: BLOCK (change to ≥ 80 for more lenient)
  
  4. Monitor outcomes: Compare decisions vs actual delivery success rates
